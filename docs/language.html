The profile language

Everything a profile does is said with a handful of small rules. This page is each one: what it means, what it is for, and an example you can move. The words in bold are the editor's; the ones in code are what the profile file stores.

A lamp asks Under what conditions?

Each lamp and backlight on a panel gets a row. The row picks cockpit signals and tests them, and the answer is a brightness, 0 up to what the lamp takes.

signal → test → and / or → brightness
A screen asks Which cells, fed by what?

A page puts fields on a screen. Each field is a run of cells and a chain of pieces, typed text or readings, and the answer is characters.

signal → reading → pieces → cells
Lamps, part 1

Tests: when a signal lights a lamp

A condition is one signal and one test. The signal is anything DCS-BIOS exports for the aircraft, not only its lamps: a switch, a selector, a gauge, a lighting knob. The test is chosen from what that signal can report, so a two position switch is offered is exactly with its positions named, and a gauge is offered numbers inside its range.

On is how bright the lamp goes when the test holds, and at zero is what it shows when the answer is zero. An indicator takes only on or off; a dimmer takes 0 to 255.

          Lamps, part 2
          
And, or: several tests on one lamp

        

        

          

            + Add condition adds a test that must also hold.
            + Add alternative (or) adds another way to light the lamp. Together they
            make a list of ANDs joined by OR, which says any rule you need with no brackets to misread.
          

          

            Each has a one sentence rule. Within a group, the lamp takes the dimmest value any
            condition asks for. For on and off tests that is AND; for a scaled backlight it is a
            dimmer behind a switch. Across alternatives, the brightest group wins. For on and
            off that is OR; for dimmers, the live branch supplies the value while the gated ones sit at zero.

          Lamps, part 3
          
Other ways to drive a lamp

        

        

          

            A row drives its lamp in exactly one of four ways: conditions, alternatives,
            Always on or Match another lamp. The editor offers
            each only where it can mean something, so a row never carries two answers to one question.
          

        

        

          

            
Always on

            
Lit whenever the aircraft is loaded, reading nothing. On a dimmer, On sets a fixed brightness.

            
{ "led": "SL", "always": true }
{ "led": "Backlight", "always": true, "on": 175 }

            
Use it for a lamp with no cockpit counterpart, or a steady backlight. Every shipped profile holds its backlights at 175 this way.

          

          

            
Match another lamp

            
Follow another dimmer, on this panel or another, as a link rather than a copy. Change the one, and every lamp matching it follows.

            
{ "device": "CarrierAce_MFD_L",
  "led": "INST_PNL_Backlight",
  "same_as": "INST_PNL_Backlight",
  "same_as_device": "CarrierAce_MFD_C" }

            
Use it for every backlight on one knob. Dimmers only, both ends, and no chains: the lamp matched must read signals of its own.

          

          

            
At zero: a floor

            
When a row resolves to zero, the lamp shows its At zero value instead. A lamp matching another keeps its own.

            
{ "led": "FLAG", "same_as": "Backlight",
  "off": 255 }

            
Use it for lamps that must stay readable by day. The PTO2's SL and FLAG are gates over other lamps; at 0 they hide them, and the editor cautions.

          

          

            
Not set yet

            
A row with no conditions is a placeholder: listed, not decided, and driven off. Not the same as Always on, which is a decision.

            
{ "led": "Master_Caution", "conditions": [] }

            
Use it for nothing on purpose: it is simply how a lamp nobody has looked at yet reads.

          Whole panels
          
Leaving a panel alone, and one panel under several names

        

        

          

            
Drive this panel

            

              Untick it and this aircraft never writes to that panel, which keeps whatever was last on it. Its
              rows stay in the profile, so ticking it again restores them. An unbound panel is different: it is
              still swept dark.
            

            
"disabled_devices": ["CarrierAce_UFC"]

            
Use it for the UFC and ICP on one swing arm, where one covers the other, or leaving a panel to another program.

          

          

            
Uses

            

              WinWing sells some panels under several names: the MCDU and each PFP as Captain, Co-Pilot and
              Observer, the MFD as L, C and R. uses points one name at another of the
              same hardware, which is then driven with a copy of its lamps, pages and slots.
            

            
"follows": {
  "MCDU_CoPilot": "MCDU_Captain",
  "CarrierAce_MFD_L": "CarrierAce_MFD_C" }

            
Use it for setting a panel up once. One step deep: a panel that follows cannot be followed. Every shipped profile does this.

          

        

      

    


    
    

      

        

          Screens, part 1
          
Fields: a run of cells, a chain of pieces

        

        

          

            A field names its cells, and fills them with pieces drawn end to end. The MCDU's screen is 24
            cells across and 14 rows down, counted from 0, so row 2 is cells 24 to 47.
          

          

            There are four kinds of piece. + text is characters you type.
            + a reading is a signal. + a gap draws blanks and
            takes whatever room the rest of the line leaves. + a rule is a gap drawn
            as dashes, with an optional label set in its middle.
          

          

            A chain only holds still at its ends, so a reading that loses a digit pulls everything after it
            left. Width holds a piece to that many cells whatever it reads, and
            aligned says where the value sits in its box: right for a number that counts
            down, so the digits stay pinned.

Gap

            
Measured last. Two or more split what is left evenly, the odd cell going to the earlier ones. With a width, a gap is a fixed spacer instead.

            
Use it for a label at the left and its value hard against the right, without counting blanks.

          

          

            
Rule and label

            
Dashes corner to corner. A label is centred with a blank each side, the odd dash going left, and needs its own length plus four cells.

            
Use it for naming a block of rows the way a CDU does: ----- TRIM -----.

          

          

            
Too long

            
A run is a fixed width. Content past it is cropped from the end the alignment anchors away from, and the editor warns with the count ahead of time.

            
Use it for nothing: fix it with a width, a shorter label, or a wider run.

          

        

      

    


    
    

      

        

          Screens, part 2
          
Readings: from what DCS sends to what the screen draws

        

        

          

            DCS-BIOS sends a needle as a position, 0 to 65535, and says nothing about what the dial is marked
            with. as sent draws the number it sends, which suits counters and
            selectors. converted spreads that travel across the numbers on the face,
            in a straight line, and then applies each step below in this order.
          

        

        

          

            
StepFileWhat it does

            
              
1. ConvertreadsBoth ends of the face. May start below zero ([-10, 12]) or run backwards ([100, 0]).

              
2. Rounddecimals, roundTo that many places, to the nearest, or "down" so a drum shows a digit only once it has reached it.

              
3. WrapwrapStart again from 0 every this many. After rounding, so 359.7 draws 0, not 360.

              
4. Draw asvalue_aliasesA word in place of the number, matched against what the face reads. "3", "0,1,2" or a band "-1.5..-0.1", ends included. Each may take a colour, or inverse.

              
5. Signabswithout its sign: only when no alias claimed the reading, so a band written for negatives still matches.

          Screens, part 3
          
What each glass can do

        

        

          

            Three kinds of screen take pages. The MCDU and the PFPs share a text grid that
            draws from a font, in colour and in two sizes. The UFC is a segment display, and
            the ICP's DED a pixel screen that can draw inverse. Some settings mean something
            on only one of them, and the check refuses them elsewhere rather than drawing nothing.
          

        

        

          

            
Colour

            
Per piece, on a text grid. White when left out. An alias can carry its own, so a reading can turn red in a band.

            

          

          

            
Small

            
The small font, for a CDU's labels. Fonts draw fewer characters small than large, so both sizes are checked.

            
Text grid only.

          

          

            
Colours from a signal

            
A second signal, one letter per cell, and what each letter means. The CH-47F sends each CDU line with a _COLOR twin.

            
"colours": { "source": "PLT_CDU_LINE1_COLOR",
  "codes": { "g": "green", "p": "magenta" } }

          

          

            
Substitutions

            
One character for another inside a line, for symbols a module sends as stand-ins. The A-10C sends its arrows as » and «.

            
"replace": { "~": "█" }

            
Any display. On a text grid every character it writes must be in the font.

          

          

            
Aliases

            
A whole value the glass cannot draw, swapped for one it can. The Hornet sends its scratchpad cursor as -- where the cockpit shows _.

            
"aliases": { "--": "_" }

            
Not the same as draw as: that one matches a number's reading.

          

          

            
Inverse

            
A filled box with the character knocked out. format names a second text signal marking which cells, as the F-16 DED sends DED_L1_FORMAT.

            
Glass that draws inverse, which today is the DED.

          

          

            
Seat

            
Restrict a field to one crew station. Two fields may share cells only when their seats differ, since both stations cannot be occupied at once.

            
{ "cells": "34", "source": "PLT_CHAN", "seat": 0 },
{ "cells": "34", "source": "OP_CHAN",  "seat": 1 }

            
Only on the five modules that export SEAT_POSITION.

          

          

            
Font

            
An aircraft with a CDU of its own draws in that CDU's font, which wins. Any other aircraft takes the profile's font, picked in the editor.

            
Text grid only. Until a font is picked, there is nothing to check a field against.

          

        

      

    


    
    

      

        

          Screens, part 4
          
Pages and slots

        

        

          

            A page is a named screen's worth of fields, kept in a library beside the profiles
            and shared by every profile on the same module. A profile gives each screen one
            slot per page key, and ticks the one a mission starts on. A slot shows a page,
            a Blank screen, or is Disabled.
          

          

            In flight, hold the page modifier from Settings and press a page key. Blank takes the screen dark;
            Disabled ignores the key and leaves the page up. The modifier counts only when it is the only one of
            Ctrl, Shift and Alt held, and DCS still sees the press, so keep that combination unbound there.

What to know

            
A page works in every profile on its module, and only on the screen it was drawn for. Editing a page changes it everywhere it is used; the editor lists where. Save page writes the page, apart from the profile's Save.

            
Deleting a page disables its slots rather than blanking them, so no screen goes dark that nobody chose to. The page shown is not remembered: each aircraft load starts on the start slot.
